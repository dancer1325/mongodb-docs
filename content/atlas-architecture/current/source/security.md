# Security in the Atlas Well-Architected Framework

The Security pillar of the Atlas [Well-Architected Framework](https://www.mongodb.com/resources/products/capabilities/well-architected-framework) includes features that ensure data integrity and privacy through comprehensive safeguarding measures, such as encryption at rest and in transit, fine-grained access controls, and adherence to regulatory standards. Use the following Atlas Architecture Center resources to learn about security in Atlas:

- [Network Security](https://mongodb.com/docs/atlas/architecture/network-security/) — MongoDB Atlas enforces mandatory TLS (Transport Layer Security) encryption for database connections. Restrict database access to specific IP addresses and CIDR (Classless Inter-Domain Routing) ranges and use private endpoints and VPC peering.
- [Authorization and Authentication](https://mongodb.com/docs/atlas/architecture/auth/) — Use Role-Based Access Control (RBAC) with built-in and custom roles to control operations on resources. Get recommendations on the best authentication method for production environments.
- [Data Encryption](https://mongodb.com/docs/atlas/architecture/data-encryption/) — Use encryption features in Atlas to protect data while in transit, at rest, and in use to safeguard data through its full lifecycle.
- [Compliance](https://mongodb.com/docs/atlas/architecture/compliance/) — Atlas meets a list of compliance standards to ensure that you can protect and monitor data while complying with external requirements.
- [Auditing and Logging](https://mongodb.com/docs/atlas/architecture/auditing-logging/) — Use auditing and logs to monitor and log Atlas platform activities. Get recommendations on the events you should audit.
